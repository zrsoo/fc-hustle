## Reviewed execution and retention boundary

The new implementation is in [browser/observer](../../browser/observer) and [fc_access](../../fc_access). All extension sources, the optional guarded native-read probe, and the server are locally authored, with no downloaded executable code or dependencies. The prior source review is [task_01](repository-analysis.md). Its upstream bridge captures credentials; that transport was not copied or executed. This observer sends only a positive allowlist of public configuration, numeric status, generic response shape, generic route/type, observer version, timestamp and a session-header-presence boolean. It never exports request/response bodies, full URLs, query strings, headers, cookies, session values, account balances or item/account identifiers. Unknown fields and values are rejected before retention. The identifier regexes validate public client/SKU strings that are actually observed; they do not supply default configuration values. Missing identifiers remain null.

The current public [EA compiled source](https://www.ea.com/ea-sports-fc/ultimate-team/web-app/js/compiled_2.js) was read without authentication and never executed. Its login view reads the client identifier through `getAppMain().getConfigRepository().getConfigString(EAConfigurationRepository.KEY_EADP_CLIENT_ID)`. The observer reads only that one public key from the actual page and applies the same strict string grammar. It does not enumerate the configuration repository or read other keys. This source review supports the getter, not any claim about the authenticated account. Its source hash and the local review hashes are retained in [review.json](browser-access/review.json).

`127.0.0.1:8766` is the updated sink and the only extension destination; the original sink remains on IPv4 loopback port 8765. The sink accepts POST only with an extension origin, an exact Host, bounded JSON and strict schema. It provides no arbitrary page evaluation, trading or credential API. Access/error logging is suppressed and exception text is not returned. CORS permissions are not granted to ordinary web pages. Local processes or another extension can spoof observations: this is a local read-only research bridge, not a trust boundary against a hostile machine. Successful tests use synthetic observations in temporary directories, never the live evidence path.

The server alone writes sanitized current observations after validation, with receipt time and an explicit source. `docs/research/browser-access/live.json` preserves the real original observations; the updated sink writes `live-v2.json` only when it receives a new valid observation, carrying forward validated history. Tests never write either live file. A matching authenticated GET must include a session-header presence signal, a successful status and a recognized credits/market/club response structure; a URL or HTTP 200 alone is insufficient. Two timestamped authenticated observations establish only observed continuity. Session renewal, timeout, forced expiry, reconnect after logout, and direct HTTP viability remain **UNVERIFIED** until observed. No intentional session expiry or secret rotation is attempted.
