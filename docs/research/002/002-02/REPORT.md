## Implementation

`fc_access/production_v1/prices.py` adds `PriceService.helpers` and
`NativePrices.legal_many`. Comparable selection first applies its existing
identity, availability, freshness, template and cap exclusions, then validates
unique BINs in two dependency rounds: native below(BIN), then native above of
those returned prices. Each command contains at most 32 distinct probes. Scalar
legality, minimum-bid, floor and listing checks use the same memo, so repeated
results and reciprocal checks require no extra browser delivery. No tick table
or inferred increments replace native outputs.

Memo entries belong to one service's exact account/persona/game/platform/identity
namespace, source, owner/host/worker/document/epoch binding. A changed binding
clears them. Every NativePrices operation checks its cap snapshot and binding;
loading fresh caps clears memo entries and invalidates prior snapshots for that
exact card. Failed or unvalidated batches never publish outputs. Helper evidence
does not establish current authentication or transaction success; fresh native
reads and the existing admission/write guards still establish those contracts.

`fc_access/production_v1/pricing.py` retains the same estimator and
`price_cache.py` retains the completed 86400-second cache. Pricing uses only
unsorted exact-version page 1/count 21, with at most two searches. The second
query has maxBuy exactly first_min and no discovery filters. An early rejection
does not populate the completed cache. Last-sale observations remain diagnostics.
The default X=500 remains configurable, sale tax is floor(resale/20), and native
legal flooring, exact-version caps and freshness checks remain enabled.

## Timing boundaries

- `browser/production-v1/page.js`: `ea_rtt_ms` measures each captured EA XHR
  from send to loadend using performance.now; `native_helper_ms` measures the
  actual native helper batch, including failed helper evaluation. Existing
  `native_service_ms` remains the whole page operation. The remaining browser
  time is reported separately as `browser_other_ms` by the executor.
- `fc_access/production_v1/foundation.py`: native and local operations have
  separate serialized executor metrics. `queue_ms` includes lock/cadence wait.
  `browser_bridge_ms` is observed delivery wall time less page-operation time
  and measured transport SQLite time. It includes HTTP, extension polling/IPC,
  serialization and response delivery; it is a residual, not an EA RTT estimate.
  Native and local metrics are persisted through the ordinary registry writer.
- `fc_access/sqlite_timing.py`: timed connections/cursors measure statement,
  fetch, script, commit and rollback work without recording SQL or parameters.
  QuoteCache, the transport Store and the existing Journal retain WAL/FULL
  durability. The localhost server returns the command-window transport SQLite
  duration in `X-FC-SQLite-Ms`; EdgeExecutor keeps it separately from the native
  response. This preserves the response evidence and correlation contracts.
- Registry diagnostic timing surrounds validation, JSON encoding and ordinary
  event persistence. `diagnostic_logging_ms` includes its separately reported
  `diagnostic_sqlite_ms`; `diagnostic_non_sqlite_ms` is the residual. Do not add
  the inclusive logging total to SQLite again. `Foundation.timing_summary()`
  returns cumulative measurements; take deltas around a valuation window.

Protocol 2 accepts either historical native_service_ms alone or all three page
timings. Unknown legacy timings remain null rather than fabricated EA RTTs.
Booleans, negative/nonfinite times, partial splits, unknown fields and component
sums exceeding the enclosing page duration are rejected.
